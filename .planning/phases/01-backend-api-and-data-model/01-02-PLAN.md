# Phase 1: Plan 2 - Validation Middleware, Weekly Stats Aggregator & Automated Tests

## Objective
Enforce robust request validation with Zod, implement the weekly summary calculation endpoint (`GET /api/tasks/stats/weekly`), add real-time search query filtering, build a development seed script, and establish automated integration tests using Supertest and Vitest.

## Proposed File Changes
- `Backend/src/middlewares/validate.ts`: Generic Zod request validation middleware returning detailed 400 Bad Request error payloads on failure.
- `Backend/src/validations/taskValidation.ts`:
  - `createTaskSchema`: Title required, date valid format, start/end time required, priority enum, status enum.
  - `updateTaskSchema`: Optional fields matching creation attributes.
  - `patchStatusSchema`: Status must be either 'pending' or 'completed'.
  - `queryTaskSchema`: Date, weekStart, status, and search query validation.
- `Backend/src/controllers/taskController.ts`:
  - Update `getTasks` to support search regex filtering (`$or: [{ title }, { description }]`) and date/weekStart filtering.
  - Implement `getWeeklyStats`: calculates open count, completed count, total count, progress percentage, `weekStart`, and `weekEnd` for the target week.
- `Backend/src/seed.ts`: Standalone script to populate MongoDB with tasks from the Figma mockups (e.g. "Finishing Wireframe", "Meeting with team", "Buy a cat food", "Finishing daily commission", "Doing Homework") across current and adjacent days.
- `Backend/tests/setup.ts`: Test setup configuring in-memory or mock MongoDB for isolated testing.
- `Backend/tests/task.test.ts`: Integration test suite covering:
  - `POST /api/tasks`: Valid creation (201), missing mandatory fields (400).
  - `GET /api/tasks`: Retrieval, date filtering, and search query filtering.
  - `GET /api/tasks/stats/weekly`: Verification of open vs completed count and progress ratio calculation.
  - `PATCH /api/tasks/:id/status`: Status toggling between pending and completed.
  - `PUT /api/tasks/:id`: Attribute updates.
  - `DELETE /api/tasks/:id`: Removal and subsequent 404 verification.

## Verification Steps
1. Run `npm test` in `Backend/` and ensure all test suites pass.
2. Run `npm run seed` and verify test records populate correctly.
3. Validate endpoint contracts against `01-CONTEXT.md`.
