# Phase 4: Plan 1 - Frontend API Client Integration & Optimistic State Sync (Tracer)

## Objective
Establish the frontend-to-backend communication pipeline by implementing `api.ts`, upgrading `useTasks.ts` with optimistic UI mutations, and adding a connection status indicator with graceful offline fallback.

## Proposed File Changes
- `Frontend/src/services/api.ts`:
  - Centralized HTTP client implementing `fetchTasks`, `fetchWeeklyStats`, `createTask`, `updateTask`, `toggleTaskStatus`, `deleteTask`, and `checkHealth`.
  - Respects `import.meta.env.VITE_API_BASE_URL || '/api'`.
  - Structured error extraction and handling.
- `Frontend/src/hooks/useTasks.ts`:
  - Attempts loading tasks from backend on mount and when `selectedDate` changes.
  - Optimistically updates UI state for instant responsiveness on mobile.
  - Gracefully falls back to local state if the backend is offline.
  - Exposes `isConnected: boolean` and `isLoading: boolean`.
- `Frontend/src/components/home/Header.tsx`:
  - Subtle status indicator pill showing backend connection status (green dot for "Live API", amber dot for "Demo Mode").

## Verification Steps
1. Build frontend bundle using `npm run build` with zero TypeScript errors.
2. Verify API client methods handle successful responses and network errors cleanly.
3. Verify optimistic mutations update UI immediately.
